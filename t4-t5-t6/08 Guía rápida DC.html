Guía rápida: diagrama de clases

Tu manual de arquitectura estática para diseñar las entidades y componentes del videojuego

📐 Abrir editor AS-UML ↗

1. ¿Qué es un diagrama de clases (DC)?

▶

Es el plano arquitectónico estático de nuestro sistema. Si el diagrama de casos de uso (DCU) definía el «qué» (la funcionalidad), el diagrama de clases define el «quién» (las entidades de software responsables de cumplirla).

Muestra de forma estructurada:

  • Las clases que componen nuestro juego (Personaje, Enemigo, Item).
  • Los datos o estados que almacenan (atributos).
  • Las acciones o comportamientos que pueden ejecutar (operaciones / métodos).
  • Los vínculos estructurales y reglas de multiplicidad que las conectan entre sí.

2. Actor vs. clase: ¡la distinción clave!

▶

Uno de los errores más frecuentes al pasar del Tema 4 al Tema 5 es confundir los actores (del DCU) con las clases (del DC). No son equivalentes:

👤 EXTERNO AL SISTEMA (DCU)

El actor (Jugador)

Eres tú, la persona sentada frente a la pantalla con el mando. Eres externo al programa y envías estímulos (pulsar el botón «A»).

🤖 INTERNO AL SISTEMA (DC)

La clase (Personaje)

Es el código C# que te representa dentro del motor (tu avatar). Es el MonoBehaviour en Unity con el atributo vidaActual y el método saltar().

🧭 Regla de oro: ¿Es alguien que usa el juego desde fuera? ➔ Actor (DCU). ¿Es una entidad cuyos datos y métodos tengo que programar? ➔ Clase (DC).

3. Anatomía de una clase y modificadores de visibilidad

▶

Una clase se representa mediante un rectángulo dividido en tres compartimentos (nombre en PascalCase, atributos en camelCase y operaciones en camelCase):

Personaje
- vidaActual : int
- vidaMaxima : int
- nombre : string
+ recibirDano(cantidad : int) : void
+ estaVivo() : bool
- morir() : void
TRADUCCIÓN DIRECTA A C# (UNITY)
public class Personaje : MonoBehaviour {
    private int vidaActual;
    private int vidaMaxima;
    private string nombre;

    public void recibirDano(int cantidad) { ... }
    public bool estaVivo() { ... }
    private void morir() { ... }
}

Visibilidad (encapsulación):

  • + Público (public): accesible desde cualquier otra clase.
  • - Privado (private): accesible únicamente dentro de la propia clase (¡regla de oro: los atributos son casi siempre privados -!).
  • # Protegido (protected): accesible para la propia clase y sus subclases (en jerarquías de herencia).

4. Las relaciones clave: asociación, multiplicidad, herencia y clases abstractas

▶

⚠️ Regla de oro de las relaciones

La asociación simple (línea continua con multiplicidades en ambos extremos) es tu relación por defecto. Solo añade un rombo (agregación ◇ o composición ◆) cuando modeles una relación estructural de «todo / parte».

Asociación simple y multiplicidad

Representa una conexión estructural («usa un» o «conoce a»). Debe especificar siempre la multiplicidad en ambos extremos:

1 → Exactamente uno
0..1 → Cero o uno (opcional)
* (0..*) → Cero o muchos
1..* → Al menos uno

Generalización (herencia △) y clase abstracta

Relación «es un tipo de» (Arma y Pocion heredan de Item). La punta triangular hueca (△) apunta siempre a la superclase.

Clase abstracta: plantilla que no se puede instanciar directamente. En UML su nombre se escribe en cursiva (p. ej., Enemigo).

5. El vínculo vital: agregación (◇) vs. composición (◆)

▶

Ambas modelan relaciones «todo / parte», y el rombo se dibuja siempre pegado al lado del «todo» (contenedor). Su diferencia radica en el ciclo de vida y exclusividad de las partes:

◇
VÍNCULO DÉBIL · COMPARTIBLE

Agregación (contenedor)

Las partes tienen vida propia y pueden existir aunque desaparezca el contenedor.

🧪 Prueba del ciclo de vida:

Si destruyo el contenedor, ¿las partes sobreviven? ➔ SÍ (agregación).

[Gremio] 0..* ◇─────── 1..* [Jugador]
◆
VÍNCULO FUERTE · EXCLUSIVO

Composición (posesión vital)

El «todo» posee en exclusiva a sus partes (multiplicidad 1 o 0..1 en el rombo) y las destruye cuando él muere.

🧪 Prueba del ciclo de vida:

Si destruyo el «todo», ¿sus partes mueren con él? ➔ SÍ (composición).

[Mazmorra] 1 ◆─────── 1..* [Sala]
